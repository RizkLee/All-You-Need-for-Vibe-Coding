# 2.13 前端包管理器：npm、yarn、pnpm

> 包管理器让你能方便地安装和管理第三方库，是现代前端开发的基础工具。

---

## 什么是包管理器

JavaScript 生态有海量的开源第三方库（"包"，Package），发布在 **npm Registry**（npmjs.com）上。

包管理器解决的问题：
- 安装某个库及其所有依赖
- 记录项目用了哪些库的哪个版本
- 升级、删除、发布包

---

## npm

**npm**（Node Package Manager）是 Node.js 自带的包管理器，也是最早、最普及的。

常用命令：

```bash
# 安装项目所有依赖（读取 package.json）
npm install

# 安装特定包
npm install react
npm install -D typescript    # -D: 只在开发时用

# 卸载
npm uninstall lodash

# 更新
npm update

# 运行脚本（package.json 中定义的）
npm run dev
npm run build
npm run test

# 全局安装（安装到系统，而不是当前项目）
npm install -g create-react-app
```

## package.json 详解

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "description": "我的应用",
  
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "test": "jest"
  },
  
  "dependencies": {
    "react": "^18.2.0",
    "react-dom": "^18.2.0",
    "axios": "^1.4.0"
  },
  
  "devDependencies": {
    "@types/react": "^18.2.0",
    "vite": "^4.3.0",
    "typescript": "^5.0.0",
    "jest": "^29.0.0"
  }
}
```

**版本号规则**（语义化版本，SemVer）：

```
版本格式：主版本.次版本.修订版本
          18.2.0

^18.2.0  → 允许更新次版本和修订版本（18.x.x），不能更新主版本
~18.2.0  → 只允许更新修订版本（18.2.x）
18.2.0   → 精确版本，不允许更新
*        → 最新版本（不推荐，不稳定）
```

## package-lock.json / yarn.lock

`package-lock.json` 锁定了所有依赖（包括依赖的依赖）的精确版本：

```json
{
  "react": {
    "version": "18.2.0",
    "resolved": "https://registry.npmjs.org/react/-/react-18.2.0.tgz",
    "integrity": "sha512-..."
  }
}
```

**一定要把 lock 文件提交到 Git**，这样团队所有人安装的依赖版本完全一致，避免"在我电脑上运行没问题"的问题。

## yarn

**yarn** 是 Facebook 开发的 npm 替代品，解决了早期 npm 的一些问题（速度慢、不确定性）。

```bash
yarn install       # 等同于 npm install
yarn add react     # 等同于 npm install react
yarn dev           # 等同于 npm run dev
```

yarn 引入了 `yarn.lock` 文件（类似 package-lock.json）。

---

## pnpm

**pnpm** 是目前最受推荐的包管理器，解决了 npm/yarn 的核心问题：磁盘空间浪费。

### npm/yarn 的问题

每个项目都有自己的 `node_modules`，相同的包被重复安装：

```
project-A/node_modules/react (18.2.0)   ← 一份
project-B/node_modules/react (18.2.0)   ← 又一份（完全相同）
project-C/node_modules/react (18.2.0)   ← 再一份
```

10 个项目 = 10 份 react。一个前端项目的 node_modules 动辄几百 MB。

### pnpm 的解决方案

所有包存储在**全局仓库**一份，项目的 `node_modules` 只是**符号链接（软链接）**：

```
全局存储: ~/.pnpm-store/react@18.2.0  (只有一份)
project-A/node_modules/react → 链接到全局存储
project-B/node_modules/react → 链接到全局存储
project-C/node_modules/react → 链接到全局存储
```

**结果**：安装速度更快、磁盘占用大幅减少。

```bash
# pnpm 命令几乎和 npm 一样
pnpm install
pnpm add react
pnpm dev
pnpm build
```

## 三者对比

| | npm | yarn | pnpm |
|--|-----|------|------|
| 安装速度 | 慢 | 中 | 快 |
| 磁盘占用 | 大 | 大 | 小 |
| Lock 文件 | package-lock.json | yarn.lock | pnpm-lock.yaml |
| 稳定性 | 好 | 好 | 好 |
| 推荐指数 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

**建议新项目用 pnpm**。不过大多数教程和文档还是用 npm，命令基本通用，切换成本低。

## npx：不安装直接运行

```bash
# 不需要全局安装，直接运行某个工具
npx create-react-app my-app
npx create-next-app@latest

# -y 参数：自动同意所有提示
npx -y create-next-app@latest my-app
```

npx 会临时下载并运行包，适合用一次就不需要的脚手架工具。

---

## node_modules 的本质

```bash
my-project/
└── node_modules/
    ├── react/
    ├── react-dom/
    ├── axios/
    └── ...（可能有几千个子目录）
```

- 这是一个可以删除并重建的目录（`npm install` 会重新生成）
- **永远不要提交 node_modules 到 Git**（加入 .gitignore）
- 体积通常几百 MB，这是正常的
