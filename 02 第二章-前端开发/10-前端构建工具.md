# 2.10 前端构建工具：Webpack 与 Vite

> 浏览器不能直接运行 JSX、TypeScript、SCSS，构建工具负责把这些转换成浏览器能理解的代码。

---

## 为什么需要构建工具

现代前端开发使用很多浏览器原生不支持的技术：

- **JSX** → 浏览器不认识，需要转换成 `React.createElement()`
- **TypeScript** → 浏览器只认识 JavaScript，需要编译
- **SCSS/Sass** → 需要编译成普通 CSS
- **ES Modules 的 import** → 老浏览器不支持，需要打包合并
- **图片、字体** → 需要优化和哈希命名

**构建工具**（Build Tool）做的事：

```
开发者写的代码（JSX, TS, SCSS, 模块化 JS）
         ↓ 构建工具处理
浏览器能运行的代码（纯 JS, CSS, 优化后的静态资源）
```

---

## Webpack：功能强大的老牌工具

**Webpack** 是 2012 年出现的前端打包工具，长期统治前端工程化领域。

Webpack 的核心概念：

```
入口（Entry）: 从哪个文件开始分析依赖
  ↓
依赖图（Dependency Graph）: 分析所有 import，构建依赖关系图
  ↓
Loader: 处理各种文件类型（ts-loader处理TS，css-loader处理CSS）
  ↓
Plugin: 更复杂的处理（HTML生成、代码压缩、环境变量注入）
  ↓
输出（Output）: 打包后的 bundle 文件
```

Webpack 配置文件示例（感受一下复杂度）：

```javascript
// webpack.config.js
module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js'
  },
  module: {
    rules: [
      {
        test: /\.(js|jsx)$/,
        use: 'babel-loader'
      },
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader']
      }
    ]
  },
  plugins: [
    new HtmlWebpackPlugin({ template: './index.html' }),
    new MiniCssExtractPlugin()
  ]
}
```

Webpack 的问题：**慢**。项目越大，启动和热更新时间越长，因为它每次都要重新打包整个项目。

## Vite：现代构建工具

**Vite**（法语"快"）由 Vue 作者尤雨溪开发，利用浏览器原生的 ES Modules 支持，彻底改变了开发体验。

### Vite 为什么快

开发模式下，Vite 不打包，直接利用浏览器的 ES Module：

```
浏览器请求 App.jsx
  → Vite 只编译这一个文件并返回
  → 浏览器解析 import，发现需要 Button.jsx
  → 浏览器再请求 Button.jsx
  → Vite 只编译 Button.jsx 并返回
```

而 Webpack 需要先把所有文件打包成一个大 bundle，再启动开发服务器。

结果：
- Webpack：项目启动可能需要 30秒 ~ 几分钟
- Vite：几乎瞬间启动（不管项目多大）

### 热更新（HMR）

修改代码后，页面局部更新而不刷新整个页面：

- Webpack：每次改动都要重新打包受影响的模块，慢
- Vite：只替换修改的模块，几乎实时更新

---

## Vite 配置示例

```javascript
// vite.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import path from 'path'

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src')  // @/components 路径别名
    }
  },
  server: {
    port: 3000,
    proxy: {
      '/api': 'http://localhost:8000'  // 开发时代理API请求，避免跨域
    }
  }
})
```

比 Webpack 简洁得多。

## 其他构建工具

| 工具 | 特点 | 适合场景 |
|------|------|----------|
| **Webpack** | 功能最全，配置复杂 | 老项目，需要极度定制 |
| **Vite** | 极快，配置简单 | 新项目首选 |
| **Parcel** | 零配置，开箱即用 | 简单项目 |
| **esbuild** | 用 Go 写的，极速编译 | 常作为其他工具的底层 |
| **Rollup** | 专注库的打包 | 开发 npm 库 |
| **Turbopack** | Vercel 开发，Next.js 13+ 使用 | Next.js 生态 |

Vite 底层用 **esbuild** 做 TypeScript/JSX 编译（极快），用 **Rollup** 做生产构建（产物优化好）。

---

## 构建后的产物

生产构建（`npm run build`）会生成 `dist/` 目录：

```
dist/
├── index.html
├── assets/
│   ├── index-abc123.js      # 打包后的 JS（哈希值防缓存）
│   ├── index-def456.css     # 打包后的 CSS
│   └── logo-ghi789.png      # 处理后的图片
```

这些文件是最终部署到服务器的内容，可以直接放到 Nginx、CDN 或对象存储上。

---

## 作为 Vibe Coder 你需要知道什么

你不需要手写 Webpack 配置。但你需要知道：

1. `npm run dev` → 启动开发服务器（热更新，未打包）
2. `npm run build` → 构建生产版本（打包优化）
3. `npm run preview` → 预览生产构建效果
4. 遇到构建错误，把错误信息给 AI 分析
5. Vite 是新项目的默认选择，Next.js 有自己的构建工具
