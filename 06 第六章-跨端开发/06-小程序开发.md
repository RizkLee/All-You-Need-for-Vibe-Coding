# 6.6 微信小程序与跨端小程序框架

> 小程序是中国特色的"轻应用"生态，不需要安装，依托超级 App 运行。

---

## 小程序是什么

**小程序**（Mini Program）是运行在微信、支付宝、抖音等"超级 App"内部的轻量应用。用户不需要去应用商店下载，直接扫码或搜索就能使用，用完即走。

小程序有独特的运行环境：
- 不是浏览器，不能用完整的 Web API
- 不是原生 App，但能访问部分手机能力
- 受宿主 App 平台方管控，有严格的审核规则
- 代码包有大小限制（微信小程序主包 2MB）

## 各平台小程序

| 平台 | 月活（约）| 适合场景 |
|------|-----------|----------|
| **微信小程序** | 数亿用户 | 最主流，覆盖最广 |
| **支付宝小程序** | 用户基数大 | 金融、政务场景强 |
| **抖音小程序** | 年轻用户为主 | 电商、娱乐 |
| **百度小程序** | 相对较少 | SEO 流量 |
| **QQ 小程序** | 年轻群体 | 游戏、社交 |

## 微信小程序的技术体系

微信小程序有自己的一套技术规范：

```
WXML（.wxml）  → 类似 HTML，但用微信自己的标签体系
WXSS（.wxss）  → 类似 CSS，但有部分限制
JavaScript（.js）→ 逻辑层，但运行在独特的 JS 引擎（非 V8）
JSON（.json）  → 配置文件
```

小程序的运行环境把**逻辑层**（JS）和**渲染层**（WXML/WXSS）分开运行在不同线程，通过消息通信，目的是防止 JS 阻塞 UI 渲染。这导致了一些与 Web 开发不同的坑。

## 跨端小程序框架：解决多端重复开发

如果你需要同时支持微信小程序 + 支付宝小程序 + H5 + App，难道要写四份代码？

**跨端小程序框架**解决了这个问题——写一次代码，编译到多个平台：

### Taro（京东开源）
- 使用 React 语法
- 支持：微信/支付宝/抖音/百度小程序 + H5 + React Native

### uni-app（DCloud 出品）
- 使用 Vue 语法
- 支持：所有小程序平台 + H5 + App（iOS/Android）
- 国内使用量最大，中文文档丰富

### Remax（阿里开源）
- 使用 React 语法，专注小程序端

## 小程序 vs App vs H5

很多产品团队会纠结：该做小程序、App 还是 H5？

| 对比维度 | 小程序 | Native App | H5 |
|----------|--------|-----------|-----|
| 安装门槛 | 无需安装 | 需要下载 | 无需安装 |
| 用户留存 | 低 | 高 | 低 |
| 功能限制 | 受平台限制 | 功能最全 | 受浏览器限制 |
| 推送通知 | 有限制 | ✅ 完整支持 | ❌ 受限 |
| 离线使用 | 有限 | ✅ 完整支持 | 有限 |
| SEO | 无 | 无 | ✅ |
| 审核 | 平台审核 | 应用商店审核 | 无 |
| 开发成本 | 低 | 高 | 最低 |

**典型选择策略**：
- 初期快速验证：H5 或小程序
- 高频使用产品：Native App（Flutter/React Native）
- 社交/商业流量引导：小程序（微信生态）
- 需要 SEO：H5 + Web

很多成熟产品会同时覆盖多端，各端各有侧重。

---

## 后端对小程序的支持

小程序也是"前端"的一种形式，同样需要后端 API。小程序调用后端的方式与 App 完全相同——HTTP 请求 + REST API。

特别之处：
- 微信小程序需要在微信公众平台配置**合法域名**，未配置的域名无法请求
- 可以用**微信登录**（wx.login 获取 code → 服务器用 code 换取 openid）作为用户身份，不需要用户单独注册账号
- 支付功能需要对接微信支付 API（服务端签名，不能在前端处理）
