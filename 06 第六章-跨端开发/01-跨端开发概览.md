# 6.1 跨端开发概览

> 用一套代码同时运行在 iOS、Android、Web、桌面——这是跨端开发的目标。

---

## 什么是"端"

在移动互联网时代，同一个产品往往需要运行在多个平台（"端"）：

| 平台 | 运行环境 |
|------|----------|
| Web | 浏览器（Chrome、Safari、Firefox）|
| iOS | iPhone、iPad（App Store）|
| Android | Android 手机、平板（Google Play）|
| macOS | Mac 桌面应用 |
| Windows | Windows 桌面应用 |
| Linux | Linux 桌面 |
| 微信小程序 | 微信内嵌环境 |

每个平台有不同的运行环境、UI 规范和技术要求。

---

## 原生开发 vs 跨端开发

### 原生开发

每个平台用该平台专属的技术：

```
iOS    → Swift / Objective-C + Xcode + UIKit/SwiftUI
Android → Kotlin / Java + Android Studio + Jetpack Compose
Web    → HTML + CSS + JavaScript
桌面   → 各平台原生 SDK
```

**优点**：性能最好，功能最全，体验最接近系统风格  
**缺点**：一套逻辑要写多遍，维护成本高，团队需要多种技术栈的工程师

### 跨端开发

一套代码（或一套主要逻辑），运行在多个平台：

**优点**：代码复用率高，维护成本低，团队技术栈统一  
**缺点**：性能通常略低于原生，某些平台特有功能实现复杂，UI 可能不完全符合各平台习惯

---

## 跨端的几个层次

跨端开发有不同的实现思路，带来不同程度的"原生度"：

### 层次一：WebView 套壳
把 Web 页面包在一个 WebView（浏览器组件）里，假装是 App。早期 Cordova/PhoneGap 就是这种思路。性能最差，但开发最简单——Web 开发者直接用 HTML/CSS/JS。

### 层次二：编译成原生组件
框架提供一套 UI 组件，编译时映射为各平台的原生组件。React Native 采用这种方式——`<View>` 编译为 Android 的 `View` 和 iOS 的 `UIView`。性能接近原生。

### 层次三：自绘渲染引擎
框架自带渲染引擎，不使用任何平台原生组件，在各平台的 Canvas/GPU 上直接绘制 UI。Flutter 采用这种方式。理论上可以实现最一致的跨端体验，性能极好，但 UI 风格与系统原生有差异。

---

## 主流跨端方案对比

| 方案 | 技术 | 渲染方式 | 覆盖平台 |
|------|------|----------|----------|
| **Flutter** | Dart | 自绘（Skia/Impeller）| iOS、Android、Web、桌面 |
| **React Native** | JavaScript/TypeScript | 原生组件 | iOS、Android（桌面需额外配置）|
| **Electron** | HTML/CSS/JS | WebView（Chromium）| macOS、Windows、Linux |
| **Taro / uni-app** | JavaScript | 编译到各小程序/React Native | 微信小程序、支付宝小程序等 |
| **Capacitor** | HTML/CSS/JS | WebView | iOS、Android、Web |
| **.NET MAUI** | C# | 原生组件 | iOS、Android、Windows、macOS |

---

## 跨端与 Web 技术的关系

一个常见问题：**用了跨端框架，还需要 React、Vue 这些 Web 技术吗？**

这取决于你用的是哪种跨端方案：

| 跨端方案 | 与 Web 技术的关系 |
|----------|-----------------|
| **Flutter** | 完全独立，用 Dart 语言，不依赖 Web 技术。但你仍需要后端 API。 |
| **React Native** | 使用 React 和 JavaScript，但不是 Web，不使用 HTML/CSS |
| **Electron** | 就是 Web 技术（HTML/CSS/JS），运行在 Chromium 上 |
| **uni-app** | 使用 Vue 语法，编译到各小程序平台 |

---

## 跨端的后端需求不变

无论你用什么跨端方案，**后端都是独立的**：

```
Flutter App  ──→ REST API ──→ Node.js/Python 后端 ──→ PostgreSQL
React Native ──→ REST API ──→ 同一套后端
Web 版本     ──→ REST API ──→ 同一套后端
```

跨端框架只解决了"前端/客户端"的代码复用，后端是共享的，不需要为每个平台写一套后端。

这就是为什么学习后端、HTTP、数据库的知识，对于 Flutter 开发者同样重要——你的 App 需要和后端通信。
