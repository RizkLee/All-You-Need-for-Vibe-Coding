# 7.1 部署基础概念

> "部署"是把代码从开发者的电脑上搬到服务器上，让真实用户能访问的过程。

---

## 什么是部署

在你的电脑上运行 `npm run dev`，只有你自己能访问 `http://localhost:3000`。要让全球用户都能访问，你需要把代码放到一台**持续运行、有公网 IP 的服务器**上，这个过程叫**部署（Deploy）**。

---

## 开发环境 vs 生产环境

| 环境 | 特点 | 在哪里 |
|------|------|--------|
| **本地（Local）** | 你的电脑，快速迭代 | 你的 MacBook / PC |
| **开发环境（Dev）** | 团队共享的测试服务器 | 云服务器，内部访问 |
| **预发布环境（Staging）** | 与生产完全一致，最终测试 | 云服务器，内部访问 |
| **生产环境（Production）** | 真实用户访问的地方 | 云服务器，公网访问 |

**不能把开发环境的习惯带进生产环境**，例如：
- 生产环境不应该有调试工具开着
- 生产环境的错误信息不应该暴露给用户（不能展示堆栈追踪）
- 生产环境必须启用 HTTPS
- 环境变量（数据库密码、密钥）必须与开发环境分开

---

## 前端部署 vs 后端部署

前端和后端的部署方式有本质区别：

### 前端部署

React/Vue 应用构建后是一堆**静态文件**（HTML、CSS、JS、图片）。部署非常简单：
- 把这些文件上传到任何能托管静态文件的地方
- 用户访问时，服务器直接返回这些文件
- 没有"运行中的进程"

适合静态前端部署的服务：
- **Vercel**（Next.js 的最佳选择）
- **Netlify**（通用静态站托管）
- **GitHub Pages**（免费，适合个人项目）
- **阿里云 OSS + CDN**
- **Cloudflare Pages**

### 后端部署

后端是一个**持续运行的进程**（Node.js 服务器、Python 进程等），需要：
- 一台持续开着的服务器（VPS 或容器）
- 进程管理（确保崩溃后自动重启：PM2、Supervisor）
- 环境变量配置（数据库连接、密钥）
- 日志收集
- 监控和告警

---

## 常见的后端部署方式

### 方式一：直接部署到 VPS

**VPS**（Virtual Private Server，虚拟私有服务器）是一台你有 root 权限的云端 Linux 服务器：

```
本地代码 → SSH 上传到服务器 → 安装依赖 → 启动进程
```

操作步骤：
1. 购买 VPS（阿里云 ECS、DigitalOcean Droplet、Linode）
2. SSH 登录服务器
3. 安装 Node.js / Python 等运行环境
4. 克隆代码，安装依赖
5. 用 PM2（Node.js）或 Gunicorn（Python）启动进程
6. 配置 Nginx 作为反向代理（处理 HTTPS、路由）

**优点**：完全控制，灵活  
**缺点**：需要自己维护服务器（安全补丁、备份、扩容）

### 方式二：PaaS 平台

**PaaS**（Platform as a Service）平台帮你管理服务器，你只需要推代码：

| 服务 | 特点 |
|------|------|
| **Railway** | 简单、便宜，部署 Node.js/Python/Go 友好 |
| **Render** | 免费套餐（会休眠），支持 Web Service + 数据库 |
| **Fly.io** | 基于 Docker，全球边缘部署 |
| **Heroku** | 老牌，取消免费套餐后用量下降 |
| **阿里云/腾讯云函数计算** | Serverless，按调用次数计费 |

### 方式三：容器化部署（Docker + Kubernetes）

用 Docker 打包应用，部署到容器编排平台（详见 7.3 节）。

---

## 反向代理：Nginx 的角色

**Nginx** 是目前最常用的 Web 服务器和反向代理：

```
用户 → Nginx（监听 80/443 端口）
         ↓ 反向代理
       Node.js 应用（监听 3000 端口）
```

Nginx 的职责：
- 处理 HTTPS（SSL 证书）
- 把请求转发给后端应用
- 静态文件直接由 Nginx 返回（比 Node.js 效率高）
- 负载均衡（把请求分散到多个后端实例）
- 限流、缓存

---

## Serverless：不管理服务器的部署

**Serverless（无服务器）** 不是没有服务器，而是你不需要管理服务器：

- 你只写函数（Function），不关心服务器
- 有请求时平台自动启动实例执行，执行完销毁
- 按实际调用次数和执行时间计费
- 0 流量时 0 费用（有的服务会"休眠"，第一次请求慢）

代表：AWS Lambda、Vercel Functions（Next.js API Routes 就是这个）、阿里云函数计算、Cloudflare Workers

**适合**：低流量、偶发性请求、事件驱动的场景  
**不适合**：WebSocket 长连接、对冷启动延迟敏感的场景
