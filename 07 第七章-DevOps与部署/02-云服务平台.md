# 7.2 云服务平台：AWS、GCP、Azure、阿里云

> 云服务让你租用计算资源，而不是自己购买和维护服务器。

---

## 云服务的基本逻辑

传统方式：买物理服务器 → 放到机房 → 自己维护。

**云服务**：在云服务商的数据中心里"租用"计算资源，按需付费，不需要维护硬件。这大幅降低了创业和个人开发者的基础设施成本。

云服务分三层：

```
IaaS（基础设施即服务）：租虚拟机、存储、网络
  → AWS EC2、阿里云 ECS、DigitalOcean
  → 你有最大控制权，也要做最多运维

PaaS（平台即服务）：直接跑应用，不管底层服务器
  → Heroku、Railway、Vercel
  → 专注写代码，平台管理底层

SaaS（软件即服务）：直接用现成软件
  → GitHub、Slack、Notion
  → 不需要部署，直接订阅
```

## 四大云服务商

### AWS（Amazon Web Services）

**全球最大**的云服务商，服务最全，覆盖 200+ 个产品：

| AWS 服务 | 对应功能 |
|---------|---------|
| EC2 | 虚拟机（服务器）|
| S3 | 对象存储（文件、图片）|
| RDS | 托管数据库（PostgreSQL/MySQL）|
| Lambda | Serverless 函数 |
| CloudFront | CDN |
| ECS/EKS | 容器/Kubernetes |
| API Gateway | API 管理 |
| SES | 邮件发送 |

AWS 的优势：功能最全、生态最大、技术社区丰富。  
劣势：价格较高，UI 复杂（学习曲线陡），在中国大陆访问需要特殊配置。

### GCP（Google Cloud Platform）

Google 的云服务，技术强，AI/ML 工具链最好（和 TensorFlow、Vertex AI 深度集成），Kubernetes 本身就是 Google 开源的。

### Microsoft Azure

微软的云服务，在企业市场（特别是 Windows/.NET 生态的企业）份额大。与 Microsoft 365、Active Directory 集成深。

### 阿里云

**国内最大**的云服务商，在中国大陆网络环境下访问快，有国内合规支持（ICP 备案、等保）：

| 阿里云 | AWS 对应 |
|--------|---------|
| ECS | EC2 |
| OSS | S3 |
| RDS | RDS |
| 函数计算 | Lambda |
| CDN | CloudFront |

**国内项目首选阿里云、腾讯云**，有国内数据中心，用户访问延迟低，客服支持也是中文。

## 现代开发者常用的"轻量"云服务

对于个人开发者和小团队，上面的大型云平台可能过于复杂和昂贵。这些"开发者友好"的平台更受欢迎：

| 服务 | 擅长 | 价格 |
|------|------|------|
| **Vercel** | 前端/Next.js 部署，极简 | 个人免费 |
| **Railway** | 后端服务 + 数据库 | 按量计费，便宜 |
| **Supabase** | PostgreSQL + 后端服务 | 个人免费 |
| **Cloudflare** | CDN、边缘函数、DNS | 基础免费 |
| **DigitalOcean** | VPS + 托管服务 | 便宜，面向开发者 |
| **Fly.io** | 全球边缘容器 | 小额免费 |

## CDN：让资源更快到用户手里

**CDN**（Content Delivery Network，内容分发网络）是分布在全球的节点网络，把你的静态资源（图片、CSS、JS）缓存在离用户最近的节点：

```
不用 CDN：
北京用户 → 请求 → 美国服务器（延迟 150ms+）

用 CDN：
北京用户 → 请求 → 阿里云北京 CDN 节点（延迟 5ms）
                   （资源已缓存在这里）
```

前端应用部署到 Vercel、Netlify，静态资源会自动走全球 CDN。这也是为什么这些平台部署的静态网站访问速度极快。

## 多可用区与高可用

生产级应用通常需要考虑：

**可用区（Availability Zone）**：同一个地区（Region）内相互独立的数据中心，一个挂了不影响另一个。

**高可用（HA）**：在多个可用区部署，数据库做主从复制，负载均衡在多个实例间分发流量——任何单点故障都不影响整体服务。

这些是中大型项目才需要考虑的，个人项目和初期创业产品通常不需要这么复杂。
