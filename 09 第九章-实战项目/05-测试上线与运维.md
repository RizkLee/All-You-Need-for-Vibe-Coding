# 9.5 测试、上线与运维

> 代码在本地跑通只是完成了 50%，剩下的 50% 是让它稳定地服务真实用户。

---

## 1. 软件测试：保证底线的安全网

在敏捷开发中，我们不需要每次修改代码都手动点一遍所有按钮。自动化测试分三类：

**单元测试（Unit Testing）**
- 测试最小的功能单元（通常是一个函数）。
- 比如测试一个 `formatDate(date)` 函数是否能正确输出格式。
- 工具：`Jest`, `Vitest`。

**集成测试（Integration Testing）**
- 测试多个模块组合在一起是否工作。
- 比如测试组件渲染以及它与 Context/Store 的连接。
- 工具：`React Testing Library`。

**端到端测试（E2E Testing）**
- 模拟真实用户的浏览器行为。
- 自动化打开浏览器 → 输入邮箱密码 → 点击登录 → 验证是否跳转到了 Dashboard。
- 工具：`Playwright`, `Cypress`。

> **Vibe Coding 建议**：早期项目不需要追求 100% 测试覆盖率。只给**核心业务路径**（如登录、支付、核心功能）写 E2E 测试，这是投入产出比最高的。

---

## 2. 环境变量的管理

从开发走向生产，最容易犯的错就是**密钥泄露**。

项目中会有很多敏感信息：
- 数据库连接密码 (`DATABASE_URL`)
- 第三方登录密钥 (`GOOGLE_CLIENT_SECRET`)
- 支付 API 密钥 (`STRIPE_SECRET_KEY`)

**规则**：
1. 绝对不要把这些明文写在代码里。
2. 使用 `.env` 文件存储。
3. 将 `.env` 加入 `.gitignore`，绝对不要推送到 GitHub。
4. 代码中通过 `process.env.DATABASE_URL` 读取。

## 3. 一键部署上线 (Vercel)

有了 Next.js 和 Vercel，部署过程异常简单：

1. 将代码推送到 GitHub 主分支。
2. 在 Vercel 后台导入这个仓库。
3. 在 Vercel 的项目设置页，填入你在生产环境的**环境变量**。
4. 点击 Deploy。

Vercel 会自动：
- 运行 `npm run build` 打包代码。
- 将静态文件分配到全球 CDN 节点。
- 将 Server Components 和 API 部署为 Serverless 边缘函数。
- 自动配置 HTTPS 证书。

之后，你每次 `git push`，Vercel 都会自动触发构建并平滑上线。

---

## 4. 绑定自定义域名

默认的 `your-project.vercel.app` 不适合对外服务。

1. 在 Namecheap 或 Cloudflare 购买你的域名 `taskflow.app`。
2. 在 Vercel 后台点击 Domains -> Add Domain。
3. 按照提示，去你的域名注册商的 DNS 设置里，添加一条 `A 记录` 指向 Vercel 的 IP，或添加一条 `CNAME 记录`。
4. 等待几分钟解析生效，Vercel 会自动为你生成 SSL 证书。

---

## 5. 监控与运维

上线不是结束，而是开始。用户可能会遇到你本地没测出来的 bug，你需要：

**错误追踪 (Error Tracking)**
你不可能每天去翻服务器日志。接入 **Sentry**。当用户的浏览器报错，或者服务器端崩溃时，Sentry 会立即通过邮件或 Slack 通知你，并附带错误发生时的完整代码堆栈和用户的环境信息。

**性能监控 (Web Analytics)**
- **Vercel Analytics** 可以在 Vercel 面板直接开启，用来查看用户的访问量、来源国家、以及网页的核心性能指标（打开耗时等）。
- **Google Analytics / Umami** 用于追踪用户点击了哪些按钮，页面停留时间，分析转化率。

**数据库备份**
对于托管在 Supabase 的数据库，平台提供了自动的每日备份（PITR）。如果是因为 bug 导致数据被删，可以一键恢复到过去的某个时间点。
