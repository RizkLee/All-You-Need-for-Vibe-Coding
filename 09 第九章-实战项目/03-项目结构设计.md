# 9.3 项目结构设计

> 良好的项目结构是可维护性的基础，特别是当你在全栈框架中同时处理前后端代码时。

---

## 数据库架构设计 (Schema)

在写任何代码前，先确定核心数据结构。我们在 Supabase (PostgreSQL) 中设计三张核心表：

**1. `users`（用户表，由 Supabase Auth 自动管理，我们可扩展附加信息）**
- `id` (UUID, 主键)
- `email` (String)
- `full_name` (String)
- `avatar_url` (String)

**2. `projects`（项目表）**
- `id` (UUID, 主键)
- `user_id` (UUID, 外键 -> users.id)
- `name` (String)
- `color` (String)
- `created_at` (Timestamp)

**3. `tasks`（任务表）**
- `id` (UUID, 主键)
- `project_id` (UUID, 外键 -> projects.id, 可空)
- `user_id` (UUID, 外键 -> users.id)
- `title` (String)
- `description` (Text)
- `status` (Enum: 'todo', 'in_progress', 'done')
- `priority` (Enum: 'low', 'medium', 'high')
- `due_date` (Timestamp, 可空)
- `created_at` (Timestamp)

## Next.js 项目目录结构

在 Next.js (App Router) 中，我们采用按功能域划分和按职责划分相结合的结构：

```text
taskflow/
├── app/                      # 路由层 (Pages & API)
│   ├── (auth)/               # 路由组（不影响 URL，用于共享布局）
│   │   ├── login/page.tsx
│   │   └── register/page.tsx
│   ├── dashboard/            # 面板主页
│   │   ├── layout.tsx        # 包含侧边栏的共享布局
│   │   ├── page.tsx          # 今日任务
│   │   └── project/[id]/page.tsx # 特定项目任务
│   ├── api/                  # 后端 API 路由 (如果需要的话)
│   ├── layout.tsx            # 根布局 (包含全局 Providers)
│   └── page.tsx              # 营销落地页
│
├── components/               # UI 组件层
│   ├── ui/                   # 通用基础组件 (如 Button, Input - 来自 shadcn/ui)
│   ├── tasks/                # 业务组件: 任务相关 (TaskList, TaskCard)
│   └── layout/               # 业务组件: 布局相关 (Sidebar, Header)
│
├── lib/                      # 核心配置与工具函数
│   ├── supabase/             # Supabase 客户端初始化
│   │   ├── client.ts         # 浏览器端客户端
│   │   └── server.ts         # 服务端客户端
│   └── utils.ts              # 通用工具函数 (如日期格式化)
│
├── types/                    # TypeScript 类型定义
│   ├── database.types.ts     # Supabase 生成的数据库类型
│   └── index.ts              # 业务组合类型
│
├── hooks/                    # 自定义 React Hooks
│   └── use-tasks.ts          # 封装任务的数据获取逻辑 (React Query)
│
├── .env.local                # 本地环境变量 (千万不要提交到 Git！)
├── package.json
└── tailwind.config.ts        # 样式配置
```

## 结构设计的几个核心原则

**1. 隔离 UI 与业务逻辑**
在 `components/ui/` 中的组件（如 `Button`）应该是"笨组件"，它们只负责展示，不知道"任务"或"用户"的概念。
在 `components/tasks/` 中的组件是"智能组件"，它们知道业务逻辑，可以调用数据。

**2. 统一的数据访问层**
不要在组件里到处散落 `fetch` 或 `supabase.from('tasks').select()`。
最佳实践是将数据获取逻辑封装在 `hooks/`（客户端端）或 `lib/services/`（服务端）中。组件只负责调用 `const { data: tasks } = useTasks()`。

**3. 服务端与客户端分离**
Next.js 最大的威力在于 Server Components。
- 默认所有组件都是服务端的（直接查数据库，速度快，不发 JS 到浏览器）。
- 只有需要交互（点击事件、`useState`）的组件，才在文件顶部加上 `'use client'`。
- 尽量把 `'use client'` 推到组件树的叶子节点，保持大框架在服务端渲染。

**4. 类型优先**
利用 Supabase 的 CLI 工具，根据数据库表结构直接生成 `database.types.ts`。这样你在写代码时，获取出来的 `task.title` 就会有自动补全，且拼错字段会直接报错。
