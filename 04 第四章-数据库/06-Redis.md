# 4.6 Redis——缓存与内存数据库

> Redis 把数据存在内存里，读写速度极快，是高性能系统中几乎必不可少的组件。

---

## Redis 是什么

**Redis**（Remote Dictionary Server）是一个开源的内存数据库，支持多种数据结构（字符串、哈希、列表、集合、有序集合等）。

最关键的特点：**数据存在内存中**，访问速度是纳秒级别，比从磁盘读取的 PostgreSQL 快几个数量级。

但内存是有限且昂贵的，所以 Redis 通常不存储全量数据，而是作为**缓存层**或**辅助存储**。

---

## Redis 的典型使用场景

### 1. 缓存（最核心的用途）

```
没有缓存：
用户请求 → 后端 → 数据库查询（50ms）→ 返回

有 Redis 缓存：
用户请求 → 后端 → Redis 查询（0.1ms）→ 返回（缓存命中）
         → 后端 → Redis 未命中 → 数据库查询 → 存入 Redis → 返回
```

适合缓存的数据：不经常变化、查询频繁的数据。
- 用户信息（个人资料页）
- 商品详情
- 排行榜
- 配置信息

缓存的核心问题是**过期策略**：数据变了，缓存里的旧数据何时更新？常见策略：
- 设置 TTL（Time To Live，过期时间），过期后下次请求重新查数据库
- 数据更新时主动删除或更新对应缓存

### 2. Session 存储

Web 应用的用户 Session 数据通常存在 Redis 里，比存数据库更快：

```
用户登录 → 创建 Session → 存入 Redis（设置过期时间）
后续请求 → 从 Redis 读取 Session → 验证用户
```

### 3. 消息队列（轻量级）

Redis 的 List 和 Stream 可以用作简单的消息队列：

```
生产者 → 把任务推入 Redis List
消费者 → 从 Redis List 取出任务并处理
```

适合简单任务队列（发邮件、发短信、生成报告）。复杂场景用 RabbitMQ 或 Kafka。

### 4. 实时排行榜

Redis 的**有序集合（Sorted Set）**天然适合排行榜：元素有分数，自动按分数排序，查询排名极快。

```
给用户 "user:1" 增加 50 分
查询排行榜前 10 名
查询用户 "user:1" 的排名
```

游戏积分榜、帖子热度排序都可以用这种方式。

### 5. 限流计数器

记录某个 IP 或用户在一段时间内的请求次数：

```
每次请求：将 "rate:ip:192.168.1.1" 的值 +1
检查：如果超过 100 次/分钟，拒绝请求
TTL 设为 60 秒，到期自动清零计数
```

### 6. 发布/订阅（Pub/Sub）

在微服务架构中，Redis Pub/Sub 可以实现服务间的实时消息传递，常用于让多台 WebSocket 服务器同步消息。

### 7. 分布式锁

当多个服务实例同时处理可能冲突的操作（如库存扣减）时，用 Redis 实现分布式锁，确保同一时刻只有一个实例在操作：

```
服务实例 A：尝试获取 "lock:product:123"
  → 成功：执行库存扣减，完成后释放锁
服务实例 B：同时尝试获取同一把锁
  → 失败：等待或返回"操作进行中"
```

## Redis 的数据结构

| 数据结构 | 描述 | 典型用途 |
|----------|------|----------|
| **String** | 字符串/数字 | 缓存、计数器 |
| **Hash** | 字段-值映射（类似对象）| 缓存用户信息 |
| **List** | 有序列表 | 消息队列、最近访问记录 |
| **Set** | 无序集合，元素唯一 | 标签系统、共同好友 |
| **Sorted Set** | 带分数的有序集合 | 排行榜 |
| **Stream** | 持久化消息流 | 事件日志、消息队列 |

---

## Redis 的持久化

"内存数据库"不意味着数据会丢失——Redis 支持将内存数据定期写入磁盘：

- **RDB**：定时快照，每隔一段时间把全量数据存到文件
- **AOF**：追加写日志，记录每次写操作，可以精确恢复

生产环境通常同时开启两种，兼顾性能和数据安全。

---

## Redis 和主数据库的关系

Redis 是**配角**，不是替代品。它在主数据库（PostgreSQL）之前提供一层高速缓冲：

```
前端 → 后端 → [Redis缓存层] → [PostgreSQL主库] → [磁盘]
                  ↑
               命中则直接返回
```

**Dragonfly** 和 **Valkey** 是近年出现的 Redis 兼容替代品，性能更高，但 Redis 依然是最成熟的选择。
