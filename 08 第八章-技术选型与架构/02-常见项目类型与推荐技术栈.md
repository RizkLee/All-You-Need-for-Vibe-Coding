# 8.2 常见项目类型与推荐技术栈

> 不同类型的项目有截然不同的需求，技术栈也应随之调整。

---

## 类型一：内容展示网站（官网、博客、文档）

**特征**：内容主导，交互少，SEO 重要，更新频率不高。

**推荐技术栈**：

| 层级 | 推荐 | 原因 |
|------|------|------|
| 框架 | **Next.js SSG** 或 **Astro** | 静态生成，极快，SEO 最好 |
| 样式 | Tailwind CSS | 快速定制 |
| 内容管理 | **Contentful** / **Sanity** / **Notion API** | 无需管理后端，编辑器友好 |
| 部署 | Vercel 或 Cloudflare Pages | 免费，全球 CDN |
| 数据库 | 通常不需要 | 内容存在 CMS |

**Headless CMS**：内容管理系统（CMS）只负责内容编辑和存储，通过 API 把内容提供给前端框架渲染，与传统 CMS（WordPress 直接输出 HTML）不同。

---

## 类型二：SaaS Web 应用（任务管理、项目工具、数据分析）

**特征**：用户登录，个人化数据，复杂交互，需要持续迭代。

**推荐技术栈**：

| 层级 | 推荐 |
|------|------|
| 前端框架 | **Next.js**（React）|
| 样式 | Tailwind CSS + shadcn/ui（组件库）|
| 后端 | Next.js API Routes 或独立 Node.js |
| 数据库 | **PostgreSQL**（Supabase 或 Neon 托管）|
| 认证 | **Clerk** 或 **NextAuth.js** |
| 缓存 | Upstash Redis（Serverless Redis）|
| 支付 | **Stripe** |
| 邮件 | **Resend** 或 **SendGrid** |
| 部署 | Vercel（前端）+ Railway（后端服务）|

---

## 类型三：电商平台

**特征**：商品管理、购物车、订单、支付、库存，有较高并发要求。

**小型电商**：

| 层级 | 推荐 |
|------|------|
| 框架 | Next.js（SSR + SSG 混合）|
| 数据库 | PostgreSQL（订单、用户）|
| 支付 | Stripe / 微信支付 / 支付宝 |
| 文件存储 | AWS S3 / 阿里云 OSS（商品图片）|
| 搜索 | Algolia 或 Meilisearch |

**也可以考虑**：Shopify（SaaS 电商平台，有 App 扩展能力，避免自建）

---

## 类型四：实时应用（聊天、协作工具）

**特征**：多用户实时同步，消息推送，在线状态。

| 层级 | 推荐 |
|------|------|
| 前端 | React / Next.js |
| 实时通信 | **Socket.io** 或 **Supabase Realtime** |
| 后端 | Node.js（事件驱动，适合实时）|
| 数据库 | PostgreSQL + Redis（消息 Pub/Sub）|
| 文件传输 | AWS S3 |

---

## 类型五：移动端 App

**特征**：iOS + Android，离线能力，设备功能集成（相机、推送）。

| 场景 | 推荐 |
|------|------|
| 全新 App，追求一致 UI | **Flutter** + Dart |
| 已有 React 经验 | **React Native** + Expo |
| 需要 AI 功能的 App | Flutter/RN + Python 后端（FastAPI）|

**通用后端**（不论哪个客户端框架）：

| 层级 | 推荐 |
|------|------|
| API | REST（Node.js 或 Python FastAPI）|
| 数据库 | PostgreSQL（Supabase 最方便）|
| 认证 | Supabase Auth 或 Firebase Auth |
| 推送通知 | Firebase Cloud Messaging（FCM）|
| 文件存储 | Supabase Storage 或 AWS S3 |

---

## 类型六：AI 产品（Chatbot、AI 工具）

**特征**：调用 LLM API，流式输出，可能需要 RAG（检索增强生成）。

| 层级 | 推荐 |
|------|------|
| 前端 | Next.js（支持 Server Components 流式渲染）|
| 后端 | Next.js API Routes 或 Python FastAPI |
| AI 框架 | **LangChain** / **Vercel AI SDK** |
| 向量数据库 | **Pinecone** / **Supabase pgvector** |
| LLM | OpenAI API / Claude API / 本地模型 |
| 流式输出 | SSE（Server-Sent Events）|

---

## 类型七：后台管理系统

**特征**：内部使用，表格、表单、数据可视化为主，不需要太强的 SEO。

| 技术 | 推荐 |
|------|------|
| 前端框架 | React + Ant Design 或 Vue + Element Plus |
| 低代码方案 | Refine.dev / AdminJS / Retool |
| 数据可视化 | ECharts / Recharts / D3.js |

---

## 技术栈不是一成不变的

产品随着用户量增长，技术栈也会演进：

```
阶段 1（0→1，验证方向）：
  全用 Supabase，极速上线，不自建后端
  
阶段 2（1→10，快速增长）：
  自建后端服务，更多控制权
  加入 Redis 缓存，优化热点接口
  
阶段 3（10→100，规模化）：
  数据库读写分离
  引入 CDN
  开始考虑微服务拆分
  
阶段 4（100→∞，成熟阶段）：
  Kubernetes 编排
  多区域部署
  专门的 DevOps 团队
```
