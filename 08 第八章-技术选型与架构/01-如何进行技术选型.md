# 8.1 如何进行技术选型

> 技术选型不是选"最好的技术"，而是选"最适合当前情况的技术"。

---

## 技术选型的常见误区

**误区一：追求"最先进"的技术**  
技术永远在演进，没有永远最新的。选最新不代表最合适，成熟稳定的技术往往更可靠，社区资源也更丰富。

**误区二：照抄大公司的技术栈**  
Netflix 用 Java 微服务，是因为他们有数百个服务、数千名工程师。一个 5 人创业团队用同样的架构只会被复杂度压垮。

**误区三：用技术炫技**  
选技术是为了解决业务问题，不是为了简历好看。

**误区四：一开始就过度设计**  
先把产品做出来，验证方向，性能问题大多数时候在你真的遇到之前都不是问题。

---

## 技术选型的核心考量维度

```
团队因素
  ├── 团队现有技术栈是什么？（学习成本）
  ├── 团队规模？（大团队需要更规范的架构）
  └── 是否有对应技术的招聘需求？

项目因素
  ├── 项目类型（内容网站、SaaS、App、工具？）
  ├── 预期数据规模和并发量
  ├── 是否有 SEO 需求？
  ├── 是否需要实时功能？
  └── 上线时间要求？

业务因素
  ├── 是否在中国大陆服务？（影响服务商选择）
  ├── 数据合规要求？
  └── 预算？
```

## 系统性的选型思路

### 第一步：明确产品形态

```
是 Web 应用？
  → 前后端分离 or 全栈框架（Next.js）

是 App？
  → Flutter / React Native

是桌面应用？
  → Electron / Tauri

是内容网站？
  → Next.js SSG / Astro

需要同时覆盖多端？
  → 哪个端是主要端，从主要端的最优技术出发
```

### 第二步：确定数据模型

```
数据有固定结构，有大量关联关系？
  → PostgreSQL

数据结构灵活，无固定 Schema？
  → MongoDB（谨慎，大多数情况 PostgreSQL 的 JSONB 就够了）

需要高速缓存？
  → Redis（通常是 PostgreSQL 的补充，不是替代）
```

### 第三步：选择后端语言和框架

```
团队有 JS/TS 经验，或想用一门语言？
  → Node.js（Express / NestJS / Next.js API Routes）

团队有 Python 经验，或需要 AI 集成？
  → Python（FastAPI 首选）

进大厂、企业级项目？
  → Java + Spring Boot

追求极致性能，团队有 Go 经验？
  → Go + Gin/Fiber
```

### 第四步：选择前端技术

```
Web 前端？
  → React（生态最大，就业市场最好）
  → Vue（中文社区好，上手快）
  → 配合 Tailwind CSS

要做全栈，减少配置？
  → Next.js（React）/ Nuxt.js（Vue）
```

### 第五步：选择部署方案

```
个人项目、小团队、初期创业？
  → Vercel（前端）+ Railway/Render（后端）+ Supabase（数据库）
  → 一分钟部署，不需要运维知识

有一定用户量，需要更多控制？
  → VPS（阿里云/DigitalOcean）+ Docker + CI/CD

大型系统？
  → Kubernetes + 多云或主要云商（AWS/阿里云）
```

---

## 技术债（Technical Debt）

选型时还需要考虑：这个选择将来改起来有多难？

**技术债**是指为了短期快速，做出的不够完善的技术决定，未来需要"还债"（重构）。

有些债值得欠（先做出来，验证方向，再优化），有些债要尽量避免（选了一个难以迁移的数据库，未来换库代价极大）。
