# 5.4 其他全栈方案一览

> 除了 Next.js 和 Nuxt.js，还有几个值得了解的全栈框架和方案。

---

## Remix

**Remix** 是另一个基于 React 的全栈框架，由 React Router 的作者开发，后被 Shopify 收购。

Remix 的设计哲学与 Next.js 有明显不同：

- **强调 Web 基础**：充分利用 HTML 表单、HTTP 缓存等原生 Web 能力，而不是用 JavaScript 模拟
- **Loader / Action 模型**：每个路由有 `loader`（获取数据）和 `action`（处理表单提交），数据流更清晰
- **嵌套路由 + 并行加载**：父子路由同时加载数据，避免串行瀑布
- **无需客户端 JS 也能工作**：渐进增强的设计理念

Remix 在某些场景下比 Next.js 更适合：内容驱动的网站、表单密集的应用、需要细粒度控制加载状态的场景。

---

## SvelteKit

**SvelteKit** 是 Svelte 框架的全栈版本。Svelte 与 React/Vue 的本质区别在于：

```
React/Vue：运行时框架（把框架代码打包进去，在浏览器里运行）
Svelte：编译时框架（把组件编译成原生 JS，没有运行时开销）
```

Svelte 写法非常简洁，没有 JSX，不需要 `useState`，直接操作变量就能触发更新：

```svelte
<script>
  let count = 0
</script>

<button on:click={() => count++}>
  点了 {count} 次
</button>
```

SvelteKit 的优势：打包体积小、性能高、代码简洁。劣势：生态相对较小，招聘市场不如 React 成熟。

---

## Astro：内容网站的最佳选择

**Astro** 的定位与上面几个不同，它不是通用的全栈框架，而是专门为**内容型网站**（博客、文档、营销页面）设计的。

Astro 最独特的特性：**岛屿架构（Islands Architecture）**

```
一个 Astro 页面：
┌─────────────────────────────────────────┐
│  静态 HTML（无 JS，极快）                │
│  ┌──────────────────────────────────┐   │
│  │  普通 HTML 内容（文章正文、导航）  │   │
│  └──────────────────────────────────┘   │
│                                         │
│  ┌────────────────┐  ┌───────────────┐  │
│  │  Island: 搜索框 │  │ Island: 评论框 │  │
│  │  （加载React组件）│  │（加载Vue组件） │  │
│  └────────────────┘  └───────────────┘  │
└─────────────────────────────────────────┘
```

页面大部分是纯 HTML（0 JS），只有需要交互的"岛屿"才加载 JavaScript。而且这些岛屿可以是 React、Vue、Svelte 任意框架的组件混用。

**结果**：极快的初始加载速度，同时保留了所需的交互能力。非常适合文档站、博客、营销页面。

---

## Laravel（PHP）：老牌全栈框架

提到全栈不能不提 **Laravel**。它是 PHP 的现代化全栈框架，特别在传统 Web 开发领域非常成熟：

- 内置 ORM（Eloquent）、认证、队列、邮件
- Blade 模板引擎或与 Inertia.js 配合用 React/Vue
- 生态完整，文档优秀
- 托管服务：Laravel Forge、Laravel Vapor

Laravel 在内容型网站、SaaS 产品领域仍然非常流行，特别是在东南亚和欧洲市场。

---

## 全栈框架选型建议

```
想做 React 技术栈的全栈应用？
  → Next.js（首选，生态最大）
  → Remix（表单密集、内容网站）

想做 Vue 技术栈的全栈应用？
  → Nuxt.js

想做内容网站/博客/文档站？
  → Astro（极致性能）
  → Next.js SSG 也可以

想要轻量、打包体积小？
  → SvelteKit

团队有 PHP 背景？
  → Laravel
```
