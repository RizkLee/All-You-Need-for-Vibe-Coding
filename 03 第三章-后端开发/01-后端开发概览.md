# 3.1 后端开发概览

> 后端是运行在服务器上的程序，负责业务逻辑、数据处理和提供 API。

---

## 后端在全栈中的位置

```
用户 → 前端（浏览器/App）→ 后端服务器 → 数据库
                                ↓
                         第三方服务（支付、邮件、短信）
```

后端是前端和数据库之间的**中间层**，也是整个系统的核心。

---

## 后端的核心职责

### 1. 提供 API
接收前端请求，返回数据。这是后端最主要的工作。

### 2. 业务逻辑
实现应用的核心规则：
- 用户下单后，库存减少，发送确认邮件，通知仓库
- 计算购物车折扣（满减、优惠券叠加规则）
- 用户积分系统

### 3. 身份认证与授权
- 验证"你是谁"（Authentication）：用户名密码、Token
- 验证"你能做什么"（Authorization）：普通用户不能访问管理员接口

### 4. 数据持久化
与数据库交互，把数据存下来，查询并返回。

### 5. 第三方集成
- 发送邮件（SendGrid、SMTP）
- 发送短信（Twilio、阿里云短信）
- 支付处理（Stripe、支付宝、微信支付）
- 文件存储（AWS S3、阿里云 OSS）

## 一个后端服务器的基本结构

以 Node.js + Express 为例，后端的请求处理流程：

```
HTTP 请求到达服务器
     ↓
中间件处理（日志记录、解析请求体、CORS检查...）
     ↓
身份认证中间件（验证 Token）
     ↓
路由匹配（这个 URL 对应哪个处理函数？）
     ↓
Controller（业务逻辑处理）
     ↓
Service（调用数据库或第三方服务）
     ↓
返回响应（JSON 数据、状态码）
```

## 服务器的基本概念

### 监听端口
后端程序启动后，在某个端口上"监听"请求：

```javascript
// Node.js
app.listen(3000, () => {
  console.log('服务器运行在 http://localhost:3000')
})
```

### 路由（Routing）
将不同的 URL 路径映射到不同的处理函数：

```javascript
app.get('/users', getUsers)           // GET /users → 获取用户列表
app.get('/users/:id', getUserById)    // GET /users/123 → 获取单个用户
app.post('/users', createUser)        // POST /users → 创建用户
app.put('/users/:id', updateUser)     // PUT /users/123 → 更新用户
app.delete('/users/:id', deleteUser)  // DELETE /users/123 → 删除用户
```

这套 URL 设计规范就是 **REST API**（详见 3.8 节）。

### 请求与响应


## 后端与前端的边界

一个常见误区：把过多的逻辑放在前端。

| 操作 | 应该在哪里 | 原因 |
|------|------------|------|
| 表单格式验证（必填、格式） | 前端+后端都做 | 前端提升体验，后端保证安全 |
| 权限验证 | 必须在后端 | 前端代码用户可以绕过 |
| 密码加密 | 必须在后端 | 前端密钥会暴露 |
| 业务计算（折扣、税费） | 必须在后端 | 前端结果可以被篡改 |
| 数据库查询 | 必须在后端 | 数据库不能暴露给前端 |

## 后端运行环境

后端程序跑在服务器上，服务器可以是：

- **物理服务器**：放在机房的真实计算机
- **虚拟机（VPS）**：阿里云 ECS、AWS EC2
- **容器（Docker）**：轻量级虚拟化，见第七章
- **无服务器（Serverless）**：不管理服务器，按调用次数计费（AWS Lambda、Vercel Functions）

开发时，你的"服务器"就是自己的电脑，运行在 localhost。
