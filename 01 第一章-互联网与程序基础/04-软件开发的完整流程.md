# 1.4 软件开发的完整流程

> 从一个想法到一个可以用的产品，中间要经历哪些阶段？

---

## 开发流程概览

```
需求分析 → 技术选型 → 设计 → 开发 → 测试 → 部署 → 维护
```

这不是一条直线，而是**循环迭代**的过程。现代软件开发通常采用**敏捷开发**（Agile）思路：每隔 1-2 周完成一个小版本，持续交付、持续改进。

---

## 阶段一：需求分析

在写任何代码之前，先搞清楚要做什么。

关键问题：
- 这个产品解决什么问题？
- 目标用户是谁？
- 核心功能有哪些？（MVP：最小可行产品）
- 有没有类似的产品可以参考？

**产出物**：需求文档、用户故事（User Stories）

用户故事的格式：
> 作为一个[用户类型]，我希望[做某件事]，以便[达到某个目的]

例如：
> 作为一个用户，我希望能用邮箱登录，以便安全访问我的账户

---

## 阶段二：技术选型

根据需求选择合适的技术栈。主要考虑：

- 项目类型（网站、App、小程序？）
- 团队熟悉哪些技术
- 性能和扩展需求
- 时间和成本限制

技术选型详见第八章，这里只是让你知道这个步骤的存在。

---

## 阶段三：设计

设计分两类：

### UI/UX 设计
- **线框图（Wireframe）**：粗略的界面布局草图
- **原型（Prototype）**：可点击的界面模拟
- **视觉稿**：具体的颜色、字体、图标

常用工具：Figma、Sketch

### 系统设计
- **数据库设计**：有哪些表，字段是什么
- **API 设计**：有哪些接口，请求和响应格式是什么
- **架构设计**：前后端如何划分，服务如何部署

---

## 阶段四：开发

实际编写代码的阶段。通常前后端**并行开发**：

```
前端开发者                    后端开发者
     │                              │
     ├── 按 UI 稿实现界面          ├── 实现 API 接口
     ├── 对接 API（先用Mock数据）   ├── 实现数据库操作
     └── 实现交互逻辑              └── 编写业务逻辑
                    ↓
             前后端联调
               ↓
            功能完整
```

**版本控制**在这个阶段至关重要。团队使用 Git 分支协作：

```
main（主分支，生产环境代码）
  ├── develop（开发分支）
  │     ├── feature/user-login（功能分支）
  │     └── feature/product-list
  └── hotfix/fix-crash（紧急修复）
```

---

## 阶段五：测试

测试确保代码按预期工作。

| 测试类型 | 谁来做 | 工具 |
|----------|--------|------|
| 单元测试 | 开发者自己 | Jest、Vitest、pytest |
| 集成测试 | 开发者 | Supertest、Testing Library |
| 端到端测试 | QA 或开发者 | Cypress、Playwright |
| 用户测试 | 真实用户 | 内测、灰度发布 |

**Bug 的生命周期**：
```
发现 Bug → 记录（Issue）→ 指派 → 修复 → 验证 → 关闭
```

---

## 阶段六：部署

把代码从本地/开发环境发布到生产服务器，让真实用户能访问。

基本流程：

```
本地代码
  → 推送到 Git 仓库
  → CI/CD 自动触发
  → 自动运行测试（测试失败则不部署）
  → 自动构建
  → 部署到服务器
  → 用户可以访问
```

**环境分类**：

| 环境 | 用途 |
|------|------|
| 本地（Local） | 开发者自己的电脑 |
| 开发环境（Dev） | 团队共享，频繁更新 |
| 测试/预发布环境（Staging） | 模拟生产，最终验证 |
| 生产环境（Production） | 真实用户使用的环境 |

---

## 阶段七：维护与迭代

产品上线不是终点，而是新起点：

- **监控**：查看错误日志、性能指标
- **Bug 修复**：修复用户反馈的问题
- **新功能迭代**：根据用户反馈添加新功能
- **性能优化**：提升速度和稳定性
- **安全更新**：及时更新有漏洞的依赖

---

## Vibe Coding 时代的开发节奏

使用 AI 辅助开发时，流程变得更快：

```
有了想法
  → 用 AI 生成初始代码框架
  → 快速实现 MVP（最小可行产品）
  → 在浏览器中验证效果
  → 遇到问题，把错误信息给 AI 分析
  → 迭代完善
  → 用 AI 生成测试用例
  → 部署上线
```

AI 擅长的部分：
- 生成样板代码（boilerplate）
- 实现已知的设计模式
- 调试具体的报错
- 解释代码含义

你需要做的部分：
- 决定做什么（需求）
- 判断 AI 生成的代码是否正确
- 设计整体架构
- 理解技术之间的关系
