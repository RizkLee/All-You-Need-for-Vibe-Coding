# 1.5 前端与后端：分工与协作

> 理解前后端的边界，是理解全栈开发的第一步。

---

## 核心区别：代码运行在哪里

这是理解前后端最本质的区别：

| | 前端 | 后端 |
|--|------|------|
| **代码运行位置** | 用户的浏览器 / 设备 | 服务器 |
| **用户能看到代码吗** | 能（可以在浏览器开发者工具查看） | 不能 |
| **直接访问数据库** | 不行 | 可以 |
| **负责什么** | 界面展示、用户交互 | 业务逻辑、数据存储 |

---

## 前端负责什么

前端的核心职责：

1. **渲染界面**：把数据转化为用户看到的页面
2. **响应用户交互**：点击、输入、拖拽
3. **与后端通信**：发起 API 请求，处理返回的数据
4. **路由管理**：用户从一个页面跳转到另一个页面
5. **状态管理**：在内存中维护应用的当前数据状态

前端**不应该**做的事：
- 直接连接数据库（安全隐患，数据库密码会暴露给用户）
- 处理需要保密的业务逻辑（代码对用户可见）
- 存储敏感数据（用户可以清空浏览器数据）

---

## 后端负责什么

后端的核心职责：

1. **提供 API**：响应前端的请求，返回数据
2. **业务逻辑**：实现应用的核心规则（如订单计算、权限校验）
3. **数据存取**：与数据库交互，增删改查数据
4. **身份认证**：验证用户是谁，是否有权限
5. **第三方服务集成**：发送邮件、短信，调用支付接口

---

## 一次完整的交互：前后端协作过程

以"用户登录"为例：

```
1. 用户在前端页面输入邮箱和密码，点击登录按钮

2. 前端 JavaScript 收集表单数据，发起 HTTP 请求：
   POST https://api.example.com/auth/login
   Body: { "email": "user@example.com", "password": "123456" }

3. 请求到达后端服务器

4. 后端验证：
   a. 在数据库中查找该邮箱对应的用户
   b. 对比密码（实际存的是哈希值）
   c. 验证通过，生成 JWT Token

5. 后端返回响应：
   HTTP 200 OK
   { "token": "eyJhbGci...", "user": { "name": "张三" } }

6. 前端收到响应，把 Token 存到本地（localStorage）

7. 前端跳转到用户主页，并在后续请求的 Header 中带上 Token
   Authorization: Bearer eyJhbGci...
```

## API 是前后端的契约

前端和后端能独立开发，是因为它们提前约定好了 **API 接口文档**：

```
接口：获取用户信息
URL：GET /api/users/:id
请求头：Authorization: Bearer <token>
成功响应（200）：
{
  "id": 123,
  "name": "张三",
  "email": "zhangsan@example.com",
  "avatar": "https://..."
}
失败响应（401）：
{
  "error": "未授权"
}
```

有了这份文档，前端开发者可以先用**Mock 数据**（假数据）开发界面，等后端完成后再对接真实接口。

## 前后端数据流向

```
用户操作（点击、输入）
     ↓
前端处理（表单验证、数据组装）
     ↓
HTTP 请求 → [网络传输] → 后端接收
                              ↓
                         身份验证（中间件）
                              ↓
                         业务逻辑处理
                              ↓
                         数据库查询/写入
                              ↓
HTTP 响应 ← [网络传输] ← 后端返回数据
     ↓
前端更新界面（重新渲染组件）
```

## 跨域问题：CORS

因为浏览器的安全限制，前端代码只能访问同一个域名下的后端。如果前端在 `localhost:3000`，后端在 `localhost:8000`，浏览器会阻止这个请求，这就是**跨域**问题（CORS）。

解决方法很简单：在后端配置允许跨域请求：

```javascript
// Express 后端
app.use(cors({
  origin: 'http://localhost:3000'  // 允许这个来源的请求
}))
```

这个问题在开发阶段经常遇到，知道怎么处理就行。

## 全栈开发者的视角

全栈开发者需要同时理解前后端，并能在两者之间流畅切换。

**常见的"全栈"分工模式**：

| 模式 | 描述 | 适合场景 |
|------|------|----------|
| 纯前端 + 纯后端 | 两人各负责一端 | 大型团队 |
| 前端 + BFF | 前端负责界面和专属后端层 | 中型项目 |
| 全栈独立开发 | 一人负责全部 | 个人项目、小团队 |
| 全栈框架 | Next.js 等一体化方案 | 快速开发 |

BFF（Backend for Frontend）是一种模式，专门为某个前端（如移动端、Web端）定制一个轻量后端层，聚合多个微服务的数据。

---

## 前后端技术的对应关系

```
前端 React/Vue 组件   ←→   后端 API 接口
前端 路由（URL）       ←→   后端 路由处理器
前端 状态管理         ←→   后端 数据库
前端 表单验证         ←→   后端 数据校验（二道验证）
前端 权限控制         ←→   后端 权限校验（真正的验证）
```

注意：前端的权限控制只是**视觉层面**的（隐藏按钮），真正的权限必须在**后端**验证。恶意用户可以绕过前端的任何限制。
