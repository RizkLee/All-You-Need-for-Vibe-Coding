# 1.1 互联网是如何工作的

> 在学任何技术之前，先搞清楚信息是怎么在网络上传递的。

---

## 从一次请求说起

你在浏览器地址栏输入 `https://www.google.com`，按下回车，几百毫秒后页面出现了。这背后发生了什么？

这个过程大致是：

```
你的电脑
  → 找到 Google 的 IP 地址（DNS查询）
  → 与 Google 服务器建立连接（TCP握手）
  → 发送请求（HTTP/HTTPS）
  → 服务器处理并返回数据
  → 浏览器渲染页面
```

我们逐步拆解这些概念。

---

## IP 地址与域名

互联网上每台设备都有一个 **IP 地址**（Internet Protocol Address），类似于门牌号。例如 `142.250.80.46`。

但人类记不住这些数字，于是有了**域名**（Domain Name），比如 `google.com`。

**DNS**（Domain Name System，域名系统）负责把域名翻译成 IP 地址。每次你访问一个网址，你的电脑都会先向 DNS 服务器查询："google.com 对应哪个 IP？"

```
你的电脑 → DNS服务器："google.com 的 IP 是多少？"
DNS服务器 → 你的电脑："是 142.250.80.46"
你的电脑 → 142.250.80.46："我要访问你"
```

## 客户端与服务器

互联网通信的基本模型是**客户端-服务器（Client-Server）**模型：

| 角色 | 描述 | 例子 |
|------|------|------|
| **客户端** | 发起请求的一方 | 浏览器、手机App、桌面应用 |
| **服务器** | 响应请求、提供数据的一方 | 放在机房里的电脑，运行着后端程序 |

服务器本质上就是一台一直开着的电脑，它在网络上等待请求，收到请求后返回数据。

---

## TCP/IP 协议栈

网络通信依靠一套**协议**来规范数据的传输格式和流程。最核心的是 **TCP/IP 协议栈**，它分四层：

```
应用层    HTTP, HTTPS, WebSocket, FTP, SMTP...
          ↕
传输层    TCP（可靠传输）, UDP（快速传输）
          ↕
网络层    IP 协议（负责寻址与路由）
          ↕
链路层    以太网、Wi-Fi（物理传输）
```

你不需要深入理解每一层，但要知道：**HTTP 是建立在 TCP 之上的应用层协议**，它定义了客户端和服务器之间的通信格式。

**TCP vs UDP 的区别**：

- **TCP**：可靠，数据有序到达，会重传丢失的包。适合网页、文件传输。
- **UDP**：快速，但不保证可靠性。适合视频通话、游戏（轻微丢包不影响体验）。

---

## HTTP 与 HTTPS

**HTTP**（HyperText Transfer Protocol）是 Web 通信的基础协议。它规定了请求和响应的格式。

**HTTPS** = HTTP + **TLS 加密**。数据在传输过程中被加密，防止中间人窃听。现代网站基本都用 HTTPS。

一次 HTTP 交互的结构：

```
【请求 Request】
GET /index.html HTTP/1.1
Host: www.example.com
Accept: text/html

【响应 Response】
HTTP/1.1 200 OK
Content-Type: text/html

<html>...</html>
```

HTTP 的几个关键概念：
- **方法（Method）**：GET（获取）、POST（提交）、PUT（更新）、DELETE（删除）
- **状态码（Status Code）**：200 成功、404 未找到、500 服务器错误
- **请求头/响应头（Headers）**：附带的元信息，如内容类型、认证令牌等

## 端口号

一台服务器可以同时运行多个服务，靠**端口号**区分。

常见的默认端口：

| 端口 | 服务 |
|------|------|
| 80   | HTTP |
| 443  | HTTPS |
| 22   | SSH（远程登录） |
| 5432 | PostgreSQL |
| 3000 | 开发时的本地服务（Node.js常用） |

访问 `http://localhost:3000` 意思是：访问本机（localhost）的 3000 端口上运行的服务。

---

## 一次完整的网页请求流程

```
1. 你输入 https://example.com/products

2. DNS 查询：example.com → 93.184.216.34

3. TCP 三次握手（建立连接）

4. TLS 握手（因为是 HTTPS，需要加密协商）

5. 浏览器发出 HTTP GET 请求：
   GET /products HTTP/1.1
   Host: example.com

6. 服务器处理请求，查询数据库，生成响应

7. 服务器返回 HTML/JSON 等数据

8. 浏览器解析 HTML，发现需要加载 CSS、JS、图片，
   继续发起更多请求

9. 页面渲染完成，用户看到内容
```

## 关键概念小结

| 概念 | 作用 |
|------|------|
| IP 地址 | 网络中的设备地址 |
| DNS | 域名转 IP |
| TCP/IP | 数据传输的基础协议栈 |
| HTTP/HTTPS | 应用层通信协议 |
| 客户端-服务器 | 互联网通信的基本模型 |
| 端口 | 同一台机器上区分不同服务 |
