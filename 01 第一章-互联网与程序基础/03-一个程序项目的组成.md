# 1.3 一个程序项目的组成

> 一个软件项目不只是代码文件，还包括配置、依赖、文档、测试等。本节带你认识一个真实项目的结构。

---

## 代码只是冰山一角

很多初学者觉得"项目 = 代码文件"。实际上，一个完整的项目还包括：

- **依赖管理**：项目用到了哪些第三方库
- **配置文件**：数据库地址、API密钥、编译选项等
- **构建系统**：如何把源代码变成可运行的程序
- **测试**：验证代码是否正确
- **文档**：说明怎么运行、怎么部署
- **版本控制**：代码的历史记录

---

## 典型前端项目结构（React + Vite）

```
my-app/
├── public/                  # 静态资源，不经过构建处理
│   └── favicon.ico
│
├── src/                     # 源代码目录
│   ├── main.jsx             # 程序入口
│   ├── App.jsx              # 根组件
│   ├── components/          # 可复用组件
│   │   ├── Header.jsx
│   │   └── Button.jsx
│   ├── pages/               # 页面级组件
│   │   ├── Home.jsx
│   │   └── About.jsx
│   ├── hooks/               # 自定义 React Hooks
│   ├── utils/               # 工具函数
│   ├── services/            # API 请求封装
│   │   └── userService.js
│   ├── store/               # 状态管理
│   └── styles/              # 样式文件
│
├── index.html               # HTML 入口模板
├── package.json             # 项目元信息 + 依赖列表
├── package-lock.json        # 依赖的精确版本锁定
├── vite.config.js           # 构建工具配置
├── .env                     # 环境变量（不提交到Git）
├── .env.example             # 环境变量模板（可提交）
├── .gitignore               # 告诉Git忽略哪些文件
└── README.md                # 项目说明文档
```

## 典型后端项目结构（Node.js + Express）

```
my-api/
├── src/
│   ├── index.js             # 程序入口，启动服务器
│   ├── app.js               # Express 应用配置
│   ├── routes/              # 路由定义（URL 映射）
│   │   ├── userRoutes.js
│   │   └── productRoutes.js
│   ├── controllers/         # 业务逻辑处理
│   │   └── userController.js
│   ├── models/              # 数据模型（对应数据库表）
│   │   └── User.js
│   ├── middleware/          # 中间件（认证、日志等）
│   │   └── authMiddleware.js
│   ├── services/            # 业务服务层
│   └── utils/               # 工具函数
│
├── tests/                   # 测试文件
├── package.json
├── .env                     # 数据库连接字符串、JWT密钥等
└── Dockerfile               # 容器化配置
```

## 关键配置文件详解

### `package.json`（Node.js 项目必备）

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "scripts": {
    "dev": "vite",           // 运行开发服务器
    "build": "vite build",   // 构建生产版本
    "test": "jest"           // 运行测试
  },
  "dependencies": {
    "react": "^18.2.0",      // 运行时需要的库
    "axios": "^1.4.0"
  },
  "devDependencies": {
    "vite": "^4.3.0",        // 只在开发时需要的工具
    "jest": "^29.0.0"
  }
}
```

### `.env`（环境变量文件）

存储不能硬编码在代码里的敏感信息：

```
DATABASE_URL=postgresql://user:password@localhost:5432/mydb
JWT_SECRET=your-secret-key-here
API_KEY=sk-xxxxxxxx
```

**绝对不要**把 `.env` 提交到 Git，因为它包含密码和密钥。

### `.gitignore`

告诉 Git 不要追踪哪些文件：

```
node_modules/    # 依赖包，体积大，可以重新安装
.env             # 敏感信息
dist/            # 构建产物，可以重新构建
.DS_Store        # macOS系统文件
```

## 依赖管理：`node_modules` 是什么

当你运行 `npm install`，npm 会读取 `package.json`，下载所有依赖到 `node_modules/` 文件夹。

这个文件夹可能包含几万个文件，但**你永远不需要手动修改它**，也不需要把它提交到 Git。

别人克隆你的项目后，只需运行 `npm install`，就会自动重新下载所有依赖。

## 版本控制：Git 的角色

**Git** 是追踪代码变化的工具。每次提交（commit）都记录了当前代码状态。

**GitHub / GitLab** 是 Git 仓库的云端托管平台，让团队协作成为可能。

一个项目的 Git 工作流：

```
本地修改代码
  → git add .              (暂存修改)
  → git commit -m "描述"  (记录一个版本)
  → git push               (推送到远程仓库)
```

## 测试文件

软件测试有不同级别：

| 测试类型 | 描述 | 例子 |
|----------|------|------|
| **单元测试** | 测试单个函数 | 验证 `add(1, 2)` 是否返回 3 |
| **集成测试** | 测试多个模块协作 | 验证用户注册流程是否正常 |
| **端到端测试** | 模拟真实用户操作 | 用 Cypress 自动点击按钮 |

测试文件通常放在 `tests/` 或 `__tests__/` 目录，或与源文件放在一起（`Button.test.jsx`）。

## Flutter 项目结构对比

Flutter 项目结构有所不同（因为是跨端框架）：

```
my_flutter_app/
├── lib/                    # 主要代码（Dart语言）
│   ├── main.dart           # 程序入口
│   ├── screens/            # 页面
│   ├── widgets/            # 自定义组件
│   └── services/           # 网络请求等
├── android/                # Android 原生代码和配置
├── ios/                    # iOS 原生代码和配置
├── web/                    # Web 平台代码
├── assets/                 # 图片、字体等资源
├── test/                   # 测试
└── pubspec.yaml            # 类似 package.json（依赖管理）
```

注意：Flutter 用 `pubspec.yaml` 管理依赖，用 `pub` 作为包管理器，而不是 npm。

---

## 小结

| 组成部分 | 作用 |
|----------|------|
| 源代码目录（src/lib） | 实际的应用逻辑 |
| 依赖配置（package.json） | 声明用到的第三方库 |
| 环境变量（.env） | 存储密钥、数据库地址 |
| 构建配置（vite.config.js） | 控制代码如何编译 |
| 测试文件（tests/） | 验证代码正确性 |
| Git 配置（.gitignore） | 控制版本追踪 |
| 文档（README.md） | 说明项目用途和运行方式 |
